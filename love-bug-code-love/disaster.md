# 大事故设定——《零日重逢》

> 故事项目：love-bug-code-love
> 依据：premise.md / concept.md / worldbuilding.md v0.5 / characters.md v0.5（2026-10-30）
> 状态：v0.2 已确认（2026-10-30 用户定案：事故升级为 DNS 停服 + 客户隐私数据泄露双重灾难，直接终结本轮上市）
> 定位：全篇最大危机事件（分离段爆点），悬疑主线的证据源，B 段收网的标的

---

## 一、事故一句话

> 灵犀科技一次例行变更中，**权威 DNS 的关键解析参数与数据加密密钥引用配置被整段删除**——全站域名解析失效、服务中断整整两小时（P0）；更致命的是，密钥失效期间一个例行备份导出任务以**明文**写出了三家核心客户的全量用户隐私数据（姓名/身份证号/手机号/交易记录，合计约 8000 万条），并被外部安全研究员在公开可访问的备份存储桶中发现——**泄露实锤、公开披露、监管介入，本轮上市直接被毙**。

## 二、事故技术链条（专业真实律）

1. **变更背景**：上市关键期，平台侧做一次例行的配置治理变更（顺带清理"冗余"配置项）——乔曼以"降本增效、配置瘦身"为名立项，拿到变更窗口。
2. **作恶手法**：变更脚本中，一段**共享配置块**被乔曼借"帮女主 review 代码"之名碰过——这段配置块里既有权威 DNS 的核心解析参数段，也有**数据加密服务（KMS 引用）的路由配置**。她将删除范围的边界值改错一个段，清理脚本越界，把整段在用配置当作冗余配置删除。
   - 手法粗糙但杀伤力极大：一个边界值、一行 diff，正是"蠢而坏"的写照（世界规则 4）。
   - 她本意只想搞出一次"可甩锅给女主的基础设施事故"，**密钥失效导致明文备份完全在她的认知之外**——这既是"蠢"的体现，也让事故后果远超她的控制（反派做局反噬的戏剧性：她以为埋的是雷，实际引爆的是核弹）。
3. **爆发过程（两波灾难，间隔十余分钟）**：
   - **第一波（停服）**：变更上线即时生效，权威 DNS 对外下发空解析；各递归 DNS 缓存 TTL 陆续过期后全站域名无法解析——故障延迟显现，最初十几分钟无人报警，给了乔曼把"变更执行人"钉死的时间窗；监控告警雪崩，战情室拉响。
   - **第二波（泄露，致命）**：密钥引用配置被删后的十几分钟内，恰好赶上例行的**跨区备份导出任务**执行窗口——加密通道失效，导出程序按降级策略**明文写出**；又因为 DNS 失效期间运维误操作将备份桶的访问策略临时改为"公开可读"以排查问题（雪上加霜的连锁人祸，人人有份的混乱），三家核心客户的用户隐私数据明文暴露在公网可访问的存储桶里。
   - 次日上午，外部安全研究员按行业惯例（responsible disclosure）向灵犀安全邮箱发出泄露报告，同时截图已在国外安全社区小范围流传——**纸包不住火**。
4. **停服两小时的构成**（专业合理性）：
   - 前约 40 分钟：定位难——服务全绿、域名打不开，排查从应用层一路误查到网络层；
   - 中段：女主从一条不起眼的变更 diff 里看出端倪（"见微知著"的成名一役），找到被删的参数段与密钥配置；
   - 后段：恢复参数本身不难，难在**全球递归 DNS 缓存**——TTL 未到期前各地仍有用户打不开，被迫做 TTL 调整+全网刷新，硬生生把恢复期拖满两小时。
5. **影响面（量级升级后）**：
   - 停服：云服务/平台型业务，客户业务连带中断（下游客户自己的服务也挂了）；
   - **泄露：约 8000 万条用户隐私数据暴露（三家核心客户：雪山银行〔金融〕、一家电商、一家医疗健康）——金融+医疗的敏感组合把监管烈度推到顶格**；
   - 上市关键期最痛的时点——双重灾难叠加，本轮 IPO 直接终止。

## 三、嫁祸机制（女主为何背锅）

- 变更工单的**提交人是沈见微**（乔曼"帮忙 review"后把执行推给了她，或其负责的模块挂着这次变更）——工单、审批流、执行账号表面证据链全部指向女主；
- 乔曼在事故复盘会上"对事不对人"地补刀：强调变更出自女主模块、执行账号是她的；
- 女主无法自证：review 记录不完整（乔曼用的是线下口头"指导"，故意不留痕），事发时她又在休假/不在工位，时间线不利；
- **泄露的连带追责**：备份导出的降级策略与"公开可读"的临时操作虽是运维混乱，但变更的源头工单在女主名下——法务的逻辑是"变更引发连锁，变更人担首责"（制度性碾压的加强版：她背的不只是事故，是刑责级别的数据安全事故）。
- **男主的扛起**：江叙白当夜复盘时从 git 变更历史与审批时间线里查到乔曼修改边界值的初步证据，但证据链同时威胁霍振声的上市布局——霍借事故做掉旧管理层，顺势与男主达成沉默交易：他扛下"架构审核失职"退场，证据封存，女主免于追责与**刑事移送**。
- 女主得知男主为她扛锅，为保护他主动消失——分离完成。

## 四、证据散布点（世界规则 1：作恶必然留痕）

| 证据 | 位置 | 时效/限制 |
|---|---|---|
| 边界值改错的 diff | git 变更历史（乔曼 review 期间的提交） | 长期存在，但被"多人协作修改"搅浑归属 |
| 变更审批流时间线 | 审批系统 | 与乔曼线下接触女主的时间点存在矛盾 |
| CI 流水线日志 | 发布系统 | 记录了删除动作的实际执行序列 |
| **备份系统导出日志 + 存储桶访问策略变更记录** | 备份平台/云审计日志 | 记录明文导出的完整链路与"公开可读"误操作的审计痕迹——**还女主部分清白的关键旁证（她只对配置删除负责，导出降级与误操作另有其人）** |
| **KMS 审计日志** | 密钥管理系统 | 记录密钥引用失效的时间点——与乔曼 diff 的提交时间精确咬合 |
| 权限日志（谁改过脚本） | 平台权限系统 | **只保留 90 天**，A 段事发时未能及时取证；大祸期间的权限日志已随封存的"证据保全副本"留存——**副本 5 年到期即 B 段收网倒计时**（见 chapters.md） |
| 乔曼与霍振声的往来记录 | 邮件/聊天存档 | 沉默交易的旁证，B 段终极弹药 |

> 时效设计即戏剧张力：A 段证据链不完整（权限日志未及时取证、账号共用搅浑水），反派苟到 B 段；男女主双线查案，必须赶在证据自然失效前收网。

## 五、监管与商业后果（量级升级后）

- **监管双杀**：服务中断按重大事故约谈追责；数据泄露按《个人信息保护法》《数据安全法》顶格调查——**监管联合工作组进驻，罚款 + 整改 + 行政处罚直接责任人**（女主作为"变更人"一度进入行政处罚拟名单——沉默交易豁免的正是这个）；
- **刑事风险**：数据泄露情节严重涉刑，"直接责任人员"的认定成为悬在女主头上的刀（她消失的几年里始终背着"未结案"的身份——B 段她回国发展的隐形枷锁之一）；
- **集体诉讼**：三家客户的用户集体维权 + 客户方的巨额违约索赔（雪山银行最重——金融数据的泄露让这家年度最大客户彻底翻脸，B 段它反而成为女主的声援者，见下）；
- **舆论海啸**：#灵犀泄露8000万# 冲上热搜第一，职场社区匿名爆料"灵犀删库式事故"叠加发酵——公关危机的量级从行业事件升为公共事件；
- 霍振声借定责风暴做掉不听话的旧管理层数人（含推动秦立群上位又弃子），男主的"审核失职"成为各方都能接受的替罪羊；**本轮上市直接终止**（不再是延期重审——资本层面的伤害不可逆，霍对"翻案"的恐惧因此更甚）；
- **B 段钩子（升级）**：翻案 = 监管追责重启 + 灵犀（已借壳/二次冲刺上市）的上市材料重大瑕疵 + 霍振声的行政处罚与刑责风险全量暴露——他对女主与证据链赶尽杀绝的动机量级同步升级；**雪山银行在 B 段得知当年真相后，以受害客户身份公开声援女主并倒戈作证——A 段的伤口成为 B 段的弹药**（善意的最重砝码）。

## 六、与既有设定的咬合检查

- 世界规则 5（专业真实）：事故有复盘、有定级（P0）、监管介入（个保法/数安法双重）、刑事风险 ✓
- 世界规则 1（留痕）：diff/审批流/CI/权限日志/存档 + 新增备份导出日志/KMS 审计/桶策略变更记录，证据体系反而更完整 ✓
- 世界规则 4（反派粗糙）：一个边界值、一行 diff 的低级手法；且"明文备份"完全超出反派认知——她以为埋的是雷，引爆的是核弹（蠢而坏的极致） ✓
- 女主姓名意涵："见微"——她正是从那条被越界的 diff 里看出真相的人 ✓
- 上市关键期 + 云服务业务：泄露的 8000 万条数据（金融+医疗敏感组合）让"不可抗力"量级与上市终结的因果完全成立 ✓
- 分离动机强化：男主扛的不只是"失职"的名声，是把女主从**刑事移送边缘**拉回来的实质豁免——他的牺牲更重，她的愧疚更深，B 段"你连让我自己选的机会都没给我"的控诉更有分量 ✓
- B 段倒计时：公证保全副本 5 年到期（chapters.md 已定稿机制），泄露链路的新证据（备份日志/KMS 审计）一并封存于副本——收网弹药更足 ✓
