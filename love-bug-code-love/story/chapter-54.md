# 第五十四章 伪造的仓库

那个深夜，沈见微没有睡。

她把伪造的仓库 clone 到本地，开始验尸。

验尸这个词她自己都觉得重——但干着干着就承认了，这就是验尸：对象已经"死"过一次了（查无此库），现在被人重新拼起来、上了妆、摆在灵堂里，而她的工作，是当着所有吊唁者的面，指出尸体的体温。

仓库本身做得不难看。她承认这一点——伪造者是有功力的。

提交历史两百多个 commit，时间线从"前年三月"一路铺到"去年八月"，频率合理：工作日多于周末，深夜多于白天（这个细节让她嘴角动了一下——**连"工程师的作息"都伪造了**，或者说，伪造者自己的作息，恰好就是工程师的作息）。代码内容跟她的仓库相似度确实高，但不是复制——变量名改过了，函数顺序调整过，注释删了一半又补了一半自己的。像是有人把她的代码"翻译"了一遍，翻译得用心，专供比对。

两段举报信里引用的"对照代码"，端端正正躺在历史的中段，时间戳前年四月——比她的提交早五个月。如果只看仓库内部，这是无懈可击的"原创证据链"。

她喝了口浓茶，开始动手。验尸有三刀。

**第一刀，砍时间。**

GitHub 的 API 是诚实的。仓库页面不显示创建时间，但 API 显示——`created_at` 这个字段，记录的是仓库对象在 GitHub 服务器上被创建的真实时刻，改不了，藏不住。她调出 API：

**"created_at": 三天前的 23:06。**

三天前。举报信发出的第三天，深夜。

这一刀是钝刀——对方有一套现成的说辞等着："旧仓库被误删，重新上传了历史"。所以这一刀只负责放血，不负责致命。真正的杀伤在后面。

**第二刀，砍内容。**

她把伪造仓库"前年四月"的那段核心代码，逐行跟自己的历史版本做比对。比到第三十七行的时候，她停住了。

那一行是：

```
retry_queue.drop_if(generation < CURRENT_GEN); // issue #437
```

行尾的注释里，赫然写着 `issue #437`。

她自己的仓库，第 437 号 issue，提交于**去年六月**——一个外部用户报告的"多代重试队列堆积"问题。她的这行修复代码，是去年六月为响应那个 issue 加的，注释里的编号是社区的惯例：哪行代码回应了哪个 issue，一目了然，三年没断过。

现在，这行"回应了去年六月 issue 的代码"，出现在了伪造仓库"前年四月"的提交里。

**前年四月的代码，回应了去年六月的提问。**

这不是普通的穿帮——这是时间倒流的物证。伪造者拿她仓库的**当前版本**往回搬运，搬运的时候顺手把注释也搬了——但他不知道 `#437` 这个编号对应的是什么，他只是觉得"这行注释挺专业"。他抄了答案，连答案的题号一起抄了回去，然后把试卷的日期写在了出题之前。

她把 issue #437 的页面链接、issue 的创建时间、和伪造仓库里那行代码的 commit 时间，三个时间戳排成一列，截了图。这一刀下去，"重新上传历史"的说辞也死了——**没有任何"误删重传"能解释一个 issue 编号的穿越。**

**第三刀，砍结构。这是致命的一刀：不可能的合并。**

伪造的历史里有一个 merge commit，在"前年五月"，声称合并了两条开发分支。她把这个 merge 的两个 parent 都 checkout 出来，重建当时的状态——然后她笑了，笑得有点冷。

Git 的合并是有数学的。一个 merge commit 的内容，必须是它两个 parent 内容的演化：要么取自 A 分支，要么取自 B 分支，要么是两者冲突的解决结果——**但每一个"解决"，都必须由两边真实存在的行冲突而来。**

而现在，这个"前年五月"的 merge 结果里，赫然包含着一段完整的冲突解决——解决的冲突双方，一边是 A 分支"前年五月"里根本不存在的一组行（那些行在 A 分支的伪造历史里，"出现"于前年七月），另一边是 B 分支里同样"尚未出生"的代码。

**一场两个还没出生的人打的架，留下了一份正式的和解协议。**

这份协议做得很逼真——冲突标记的解决方式很老练，缩进对得整齐，像极了真人在深夜里手动解决冲突的手笔。伪造者用工具重放了合并，把最终代码灌进了历史。但他漏算了一件事：**git 的每一个对象都记得自己的 parent。**历史可以改写，改不干净的是"内容对 parent 的依赖"——内容从哪里演化而来，对象图记得清清楚楚。

伪造的历史不是一棵树。是一幅画着树的墙。

她在终端里敲完最后一行验证命令，输出滚出来：`merge contains lines not present in either parent`。她盯着这行输出看了很久，忽然想起一年多前，某个人在战情室里说过的一句话——"**痕迹不会消失，只会等待。**"

git 的对象图，等了一年多，等来了它的证人。

---

天亮的时候，验尸报告写完了。

她没有把它写成报告。她把它写成了一篇公开的技术长文——用她自己的、那个仓库维护者的身份，发在开源社区的专栏里。标题她斟酌了很久，最后定的是一个克制到近乎冷酷的版本：

**《关于近日针对本项目抄袭指控的技术核查——兼论 git 历史的不可伪造性》**

文章的框架是教科书级的冷静：先完整复述指控（附上举报信的"证据附录"，一字不改），然后逐一验证——API 时间戳、issue 编号的穿越、不可能的合并。三刀摆在正文里，每一刀配可复现的命令行和截图，任何人拿自己的电脑跑一遍，都能得到同样的输出。

文章的最后一段，她写了一句后来被转了上万次的话：

"**git 是一个只认数学的系统。它不认识指控，不认识声望，也不认识委屈。它只认识对象、哈希和 parent 指针——这既是它最冷的地方，也是它最公平的地方。伪造者可以伪造一切人类可读的东西：代码、注释、日期、甚至冲突的痕迹。但他伪造不了内容对历史的依赖。**"

"**真实是一条线的话，历史就是一张网。线可以画得很像，网的每一个结点，都连着改不掉的 parent。**"

发完是早上七点。她定了八个闹钟准备睡三小时，结果一个都没用上——文章发出的第九十分钟，评论区炸了。

先是她的仓库的贡献者们——那些散落在全球各地的、三年来跟她在同一个项目里挖过坑的网友。issue #437 的提交者本人第一个赶到评论区："等等，那个 issue 是我提的？！我在楼里作证，时间去年六月，有邮件通知为证。"随后十几个贡献者陆续赶到，各自认领了"被穿越"的代码段。开源社区的 sleeping 巨头们醒了——一个仓库的维护者被指控抄袭，全体贡献者都有资格愤怒，因为指控打击的是所有人的集体声誉。

中午十二点，文章上了社区首页。下午两点，有技术大 V 转发并附评："年度最佳开源取证文。建议每个写代码的人都读一遍——顺便记住那个 issue 编号穿越的案例，比什么教科书都直观。"

公司内部的风向，在同一天下午掉头。有人把文章转进大群，配文只有两个字："反转。"昨天还在转发"实锤仓库"的人，今天转发的是"issue 穿越"。周昊在群里发的那篇三百字长文《我知道的见微》，阅读量在下午翻了十倍。林霜的朋友圈下面，昨天问"所以到底抄没抄"的人，今天集体改口"我就说嘛"。

墙倒众人推，墙立众人扶。舆论这个东西没有记性——她早知道。所以风向掉头的时候，她没有高兴，只是把"风向"两个字记进了笔记本，标注：**不可依赖。**

---

下午四点，她做了验尸的最后一项：查凶。

伪造仓库的 owner 是一个空壳账号：注册于四天前，零 follower，零 following，没有任何其他活动——干净得像一张没有指纹的白纸。典型的干完这一票就扔的一次性身份。

账号本身查不出东西。但 git 会替账号说话——每一个 commit 的对象里，都嵌着 author 和 committer 的邮箱。

她把两百多个 commit 的元数据全部导出来，group by 邮箱。百分之九十九的提交用的是 GitHub 标准的 noreply 邮箱。但有一条例外——只有一个 commit，仓库里最不起眼的一条初始化提交，作者邮箱是：

**u237114@163.com**

u，加六位数字。

她盯着这个前缀，血往下沉。

这个格式她太熟了。灵犀的内部系统——工单、门禁、评审、每一台终端的登录账号——全部是这个格式：**u + 工号，六位。**她自己的工号是 u201847，老康是 u090312，周昊是 u182556。

u237114。一个她不认识的工号。一个在这套格式里土生土长的、真实的内部账号。

伪造者用空壳账号、noreply 邮箱、公共终端，把每一层身份都剥得干干净净——然后在一个凌晨的初始化提交里，用自己的默认 git 配置，漏出了一行自己的影子。一行七个字符的影子。

她没有去查 u237114 是谁——查不到，工号与姓名的对应关系在 HR 系统里，她没有权限，也不需要。因为这个数字此刻的功能不是"指认"，是"定性"：

**这一次，连"共用通道"都不用了。凶手第一次把爪印留在了墙外的世界，但爪印的纹路，是这家公司内部的。**

她把这一切——API 时间戳、issue 穿越、不可能的合并、u237114——全部整理进证据包，加密，存档，一式三份。然后她给核查组的正式回复通道发了一封邮件，正文只有一段：

"举报信所附'原始项目'经技术验证系伪造（详见附件：完整取证报告及可复现步骤）。伪造仓库 commit 元数据中包含一个内部账号格式的邮箱前缀，建议核查组将此线索纳入范围——**本案的性质已不是'候选人资格问题'，而是'伪造证据构陷'。**"

发完邮件，她靠在椅背上，长长地呼了一口气。

窗外，十二月的天暗得早，下午四点半，暮色已经开始往楼群的缝隙里沉。桌上的浓茶凉透了，她端起来喝了最后一口，凉茶入喉，激得人清醒。

手机震了一下。是江叙白，消息很短：

"文章看了。三刀都干净。"

隔了几秒，第二条：

"明天上午十点，技术委员会。你带着证据包来——从今天起，这案子换一个量级打了。"

她回了个"好"。回完，她看着窗外最后一点天光，忽然想起温遥昨晚临走时说的那句话——墙外的仗，你得自己打。

打完了。这一仗从凌晨十二点打到下午四点，十六个小时，她一个人，一个终端，打赢了 git 世界里的一场验尸。

但她在胜利里尝到的那点味道，不是甜的。

是铁锈味。因为 u237114 那七个字符告诉她一件事：**构陷她的这只手，没有伸到墙外去——这只手一直就在墙内。**墙外的战场、外部的平台、陌生的账号、逼真的伪造——全是障眼法。核心的恶意，始终生长在她每天刷卡进出的这栋楼里，长在她每天路过四楼时，那一间间亮着灯的办公室里。

工号是六位的。这栋楼里，六位工号的人，有一千两百个。

她翻开笔记本，写下今天验尸的最后一行结论。笔尖顿了顿，她在结论后面，添了一个只有半句的、冷冷的注脚：

**"爪印在墙外，爪子在墙内。"**

**"——现在，该查爪子了。"**
