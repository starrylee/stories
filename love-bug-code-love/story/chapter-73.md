# 第七十三章 附件 C

沈见微 review 到那份立项书，纯属流程使然。

四月下旬，加固方案进入落地阶段，配置中心统一收口是第一仗。攻坚组作为压测和技术数据支持方，名字挂在收口工程的联署名单里——这意味着所有跟配置中心相关的正式材料，都会在评审系统里给她推一份副本。

周二下午，系统推来一份待阅件：**《平台侧配置瘦身专项——立项材料归档件（含修订）》**。

按说她只需要点"已阅"。这是归档件，不是待评审件。归档件的推送是知会性质的，全公司每天在评审系统里流动的归档件有几百份，百分之九十九的命运都是被扫一眼标题然后沉进档案库。

她本来也会这样处理。

坏就坏在，她有个习惯：点开文件先看目录。

三页半的立项书，附件 A、B、C。她的目光在"附件 C：清理脚本技术说明"那一行停了半秒——因为附件 A 是配置域清单，跟她这边的压测标记有关联，她想确认清单里的配置域划分跟收口工程的口径是否一致。

她先看附件 A。没问题。十一条配置域，划分干净。

然后顺手翻到附件 C，想看看脚本的接口设计会不会跟她这边的标记数据有耦合。

前两页都是常规内容。脚本目标、模块划分、跟配置中心 API 的调用方式。她看得很快，工程师读这类文档的速度是扫读，眼睛只停在不一致的地方。

停下来的地方在第三页，参数说明区。

十几行参数。超时、并发数、重试次数、批次大小。然后是那一行：

**"清理脚本边界值：默认 86400，详见脚本实现。"**

她扫过去了。扫过去之后两秒钟，又倒回来。

不对。

不是数值不对——86400，二十四小时，作为"清理后观察窗口"很正常。不对的是**这个词的定义方式**。

她又把参数区从头读了一遍。越读越觉得硌。

超时的定义写在参数说明第一行：什么场景、什么单位、超时后干什么，清清楚楚。并发数有定义。重试有定义。唯独"边界值"这一行——**没有定义**。

一个参数，只有默认值，没有语义。它到底是什么的边界？观察窗口的下限？还是删除范围的上限？"详见脚本实现"——参数的含义要到代码里去找，这在一个归档的设计说明里，是不该出现的东西。设计说明就是用来在代码之前钉死语义的。

而且"边界值"这个词本身有歧义。在她读过的配置系统文档里，"边界值"最常见的用法是**删除/归档操作的判定边界**——超过边界的删，不超过的留。如果这行参数的本义是观察窗口，那它应该叫"观察窗口时长"。叫"边界值"，就存在另一种读法：一个决定删多深的数字。

一个词的歧义，在八万六千四百秒这个量级上，就是"观察一天"和"删掉一天以上的东西"的区别。

沈见微盯着这一行看了半分钟。

然后她笑了笑，笑自己。

多想了。这就是个命名问题——写文档的人随手用了个不严谨的词，语义八成就是观察窗口，因为"详见脚本实现"的下一版代码里大概率写得很清楚。她见过的这类小毛病没有一百也有八十，大部分的结局都是永远没人发现，小部分的结局是在某次故障复盘里被拎出来骂两句。

而且这份立项书是乔曼的团队出的。那位现在写文档的水平今非昔比，风险九条写得连方工都夸干净。干净的人偶尔留一处含糊，通常就是含糊本身。

道理都想通了。

但她的手指已经比道理快一步，点开了评审系统的评论框。

这是她的职业病，改不掉的那种。当年 TTL 三档梯度不齐，全公司人都看着曲线说"网络毛刺"，只有她要把"整齐"两个字查到底。一个定义不清的参数对她而言，就像代码里一个没注释的魔数——**你可以不处理它，但你不能假装没看见它。**

她打了一行评论。打完看了一遍，删掉了后半句"或者至少改名'观察窗口时长'以消歧义"——太啰嗦，评审评论要说最小的话。

最后留下的评论只有一行：

**"建议边界值用配置中心管理，别硬编码。另：此处参数语义建议在设计说明中补全（观察窗口 or 判定边界？）。"**

她想了想，加了个标签：**低优先级**。

发布。评论编号 CR-0417，时间周二下午 4:41。

然后她关掉文件，继续做自己的活。这件事在她的注意力队列里排了大概半小时的队，然后被晚上的压测排期挤了出去。她没有再想起它——一个低优先级的措辞建议，在一个有四百份待阅件的系统里，连一滴水都算不上。

---

评论是当晚十点被回复的。

沈见微已经下了班。她是在家洗完澡之后，习惯性看了眼工作软件——攻坚组的人都有这个习惯，收口工程期间，晚上十点看一眼告警群是义务。

没有告警。有一条评审系统的通知。

**"乔曼 回复了你的评论 CR-0417：好的，采纳。参数语义将在下一版设计说明中补全（确认为观察窗口时长，命名同步修改）。边界值参数化已排入下期迭代，感谢沈工细致。"**

沈见微看着这条回复，看了两遍。

回复本身挑不出任何毛病。采纳得爽快，认错认得体面，"感谢沈工细致"五个字落在正正好的位置——不多一分谄媚，不少一分诚意。要是让方工来看，方工大概会说：别听词，看立场。可这条回复里没有立场，只有一个高度职业的"好的"。

不知道为什么，这个"好的，采纳"让她想起另一件事。

两年多前，那个 review 的深夜，她泡着面给加固方案重写第三版，江叙白的评审意见只有两行，她逐条改完，凌晨提交。改完的那一瞬间有一种奇怪的踏实感——像把一块翘起的地砖踩平了。

而现在的这种感觉不一样。她说不上来哪里不一样。

她盯着屏幕又看了几秒，然后摇摇头，把手机扣在桌上。

想多了。一个文档措辞的采纳，能有什么不一样。

她睡了。那晚她睡得不错——压测数据出了新版本，收口工程的联调排在下周，生活里全是具体的事。具体的事是最好的安眠药。

她不知道的是，那条回复发出的时候，回复的人也没睡。

---

乔曼是在晚上十点零三分看到 CR-0417 的。

她每天晚上会过一遍自己条线所有材料的评审动态——技术秘书的职业习惯，也是她自己的纪律。CR-0417 跳出来的时候，她先看的是评论人姓名。

沈见微。

她的心跳没有变化。三年了，这个人的名字出现在她的任何系统里，她都已经不会心跳变化了。会变化的只有处理速度。

她点开评论，逐字读完。

第一遍读完，她的后背起了一层很细的汗。

**"（观察窗口 or 判定边界？）"**——括号里那六个字，像一根探针，不偏不倚扎进了附件 C 唯一的那处含糊里。她自己写那行小字的时候反复掂量过的歧义，被一行低优先级的评审评论，轻描淡写地问了出

不。

她让自己停下来，重新读第二遍。这一遍她读的是技术之外的东西。

评论的语气。低优先级。没有@任何人。没有抄送。建议式的措辞——"建议"，"别硬编码"。这是一个工程师路过一处不严谨时随手留下的钉子，钉子本身没有指向性。这个女人看到了歧义，但她没有把歧义和"人"联系起来——她把它当成了一处文档瑕疵。

如果她起了疑，评论不会是低优先级。

乔曼靠在椅背上，慢慢吐出一口气。

安全。

而且——她盯着那条评论又看了一会儿，忽然意识到一件事——

这条评论不是威胁。

这条评论是**礼物**。

"边界值用配置中心管理，别硬编码。"

她把这句话在脑子里翻过来，又翻过去。

这个建议本身是好实践，参数化，可管理，可审计。她原本的设计里，86400 是硬编码在脚本里的——那意味着边界值的任何修改都要改代码、过代码评审、留 diff。硬编码的修改是显性的。

而如果按这个建议改——边界值挪进配置中心，变成一个运行时参数——修改它只需要一次配置变更。

配置变更走什么通道？

统一收口之后：双签，留痕，窗口期。

双签的复核人是谁？立项书第九条，江叙白要求的名单报备——她自己的团队。留痕？她比谁都清楚哪份痕迹会被读、哪份不会。窗口期？变更窗口的排期表在她这个"治理流程牵头人"的案头过。

一个硬编码的、显性的、要过代码评审的数字，变成一个配置的、流程内的、被合法通道包裹的参数。

对面那个女人，亲手把她的引信，从焊死在炸弹上，改成了插在插座上。

乔曼坐在灯下，很久没有动。

然后她笑了。不是会议室里那种标准的笑，是一个人独处时才会有的笑，有点凉，有点佩服，还有一点她说不清楚的东西——像棋手看到对手随手一步棋，先是一惊，再看，发现这步棋把自己将死了。

不。还没将死。

因为这步棋有一个前提，一个对面没有意识到的前提：**这颗引信会被插到插座上，这件事本身，不能被对面知道。**

沈见微留这条评论的时候，以为自己在钉一块地砖。她不知道这块地砖下面是井口。

而井口上现在需要一个盖子。

乔曼想明白这个盖子应该怎么做，只用了不到一分钟。

她重新坐直，开始回复。措辞在心里过了三遍：

采纳。全盘采纳。爽快地、体面地、不留一丝迟疑地采纳。

然后——

她打开立项材料的评审名单管理页。

配置瘦身专项的评审名单，原本是固定的三:方工（技术委员会）、涂工的条线负责人、收口工程的接口人。名单管理页上有一个灰色的加号：**添加评审人**。

她的光标在那个加号上悬了几秒。

添加谁，有很多选择。加方工更顺理成章，加秦立群更有分量。但那些人都是"看结果"的评审——他们审报告，不审细节。

而这份材料的未来，需要的不只是被审。

需要的是**被她审过**。

乔曼点了加号，在搜索框里输入三个字：沈见微。

工号 u201847，攻坚组。系统跳出确认框："确认添加该评审人？添加后其将收到本项目后续全部材料。"

她点了确认。

---

十分钟后，沈见微的评审系统里，多了一条新通知：

**"你已被添加为「平台侧配置瘦身专项」评审人。后续材料将推送给你。添加人：乔曼。"**

这条通知躺在她的通知列表里，排在一条告警的收悉确认和两封日程邀请中间，安静，普通，像系统每天生成的几百条流程消息里的任何一条。

它不会响。不会亮。不会被任何人多看一眼。

从这一刻起——

一个评审名单上的名字，一个"建议采纳"的回复，一条"感谢沈工细致"的尾巴——嫁祸的链条上，第一环被铸了出来。它铸得如此之轻，轻到连被铸进链条里的那个人，此刻正在安睡，梦里都是压测的曲线。

配置中心的深处，那个叫"边界值"的参数，即将迎来它的搬家：从脚本里，搬到插座上。

而评审名单上新增的那个名字，将在未来某一天，被当作持刀的手，写进所有人都能看到的纸面上。

刀还没铸。

持刀的人已经入库了。

窗外，四月的夜风穿过整座城市。评审系统的服务器机房里，几万台风扇嗡嗡地转，把一条又一条流程消息，送往它们各自的、尚未知晓的命运。
