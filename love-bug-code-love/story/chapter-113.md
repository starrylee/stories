# 第一百一十三章 被删的参数段

回滚是晚上七点二十分开始的。

流程上，回滚比出事简单：基线快照在，二十三个被"归位"的参数段，原样搬回去。老涂的手很稳——他这三天大概没睡好，眼睛红着，但手不抖：这双手执行过上百次批次，此刻执行的是它此生最重要的一次逆向操作。

七点五十一分，二十三段全部回滚完成。配置中心的权威端，回到了周日晚上九点之前的状态。

理论上，恢复了。

**理论上。**

"为什么用户还在打不开？！"八点二十分，客服的反馈曲线没有掉头，有人喊了出来。

沈见微站在监控大屏前，说出了这一天最难的一句话：

"因为 TTL。"

她调出了一张图。图的横轴是时间，纵轴是全球递归服务器的缓存覆盖率——一条缓慢下降的曲线，从上午九点开始掉，现在掉到 37%。

"全球的递归 DNS 服务器，缓存里存的是**坏记录**——'这个域名不存在'或者'指向已失效节点'的记录。"她说，"这些坏记录有它们自己的 TTL，最长的一批要六个小时才过期。**我们回滚的是源头，源头是好的了——但全世界各级缓存里的坏水，要按它们自己的时间表，一截一截排干净。**"

"多久？"程亦朗问。他站在人群最后，这句话是他今晚说的第一句话。

"最好情况：调低权威端的 TTL，主动推送刷新，配合公共递归服务商的应急通道——**两个小时。**"她说，"最坏情况：部分二级运营商的递归节点不理会我们的刷新，等自然过期——**明天上午。**"

战情室安静了几秒。

有人低声骂了一句。有人开始打电话联系各家公共 DNS 的应急接口。老康从人群里挤出来，拍了拍她的肩，什么也没说——攻坚组的人知道，"最坏情况明天上午"这七个字，她一定是先算过三遍才说出口的。

**修复一个故障的时间，不由修复它的人决定，由故障自己留下的缓存决定。**这是 DNS 这门学科的残酷之处：它为稳定而生，稳定到连错误都稳定。

八点半，第二波操作开始：权威端 TTL 下调，刷新信号全网推送。曲线开始以肉眼可见的速度回升——37%，41%，48%……

就是在这段回升的间隙里，沈见微做了那件她后来被称为"见微知著"的事。

---

她没有看那条令人宽慰的回升曲线。

她坐在战情室角落的一台电脑前，把 W-041 第二十七行的 diff，重新打开，从头到尾，一行一行地看。

不是为了找故障——故障已经找到了，回滚已经做了。她看 diff 是习惯：**故障修复之后，diff 里剩下的东西，就是全部的真相。**真相值得单独看一遍。

diff 很长。二十三个参数段的迁移记录，一千四百多行。她看得很慢。

看到第三百多行的时候，她的手停了。

那是一段很小很小的记录。小到什么程度——在整个 diff 的语境里，它只是一次"顺带"：两个参数段在物理存储上相邻，同步脚本搬运第一个段的时候，把紧挨着的第二个段的一个"引用指针"也动了。改动只有一行。日志里的描述是标准的迁移用语："**相邻引用随迁**。"

随迁。

被随迁的那个引用，指向的东西，让她的目光钉在了屏幕上。

**kms-reference-routing.legacy → 密钥服务路由引用。**

这个引用，在周一凌晨之后，指向过一段"不存在"的路由——因为 KMS 的引用路由段，也在那二十三个段里。随迁发生在周日晚 23:47；回滚发生在今晚 19:51。

中间隔着多久？

她的手指在键盘上敲了两下，算了出来：**四十六个小时。**

四十六个小时里，这个引用是断的。断的引用，意味着 KMS 的**路由更新**失效——已有的密钥还能用，但所有"新发起的"密钥申请和刷新，走的都是……她去查了 KMS 的服务日志。

查询结果出来的那一瞬间，她的后背，一层一层地凉了上来。

**周一凌晨 1:58 至 2:41，KMS 服务日志里有一段异常记录：密钥申请超时，连续十一次。然后——降级。**

降级为本地会话。

她点开那十一次超时之后的日志。日志显示，在降级状态下，有一个任务周期性地申请"本地会话"，每一次都成功——因为本地会话不需要密钥服务，**它用明文。**

申请本地会话的任务名，她在系统里见过一千次，熟得像自己的名字：

**backup-export-daily。**

例行备份导出。每天凌晨两点。九年了，从未间断。

她调出了周一凌晨那次导出的记录。记录很短，状态是"成功"——**成功**。导出体量 417 GB。数据来源：三个数据库集群的全量增量。

三个集群。

她不用查编号也知道是哪三个。全公司只有三个集群的数据，会被例行导出"异地容灾"：核心交易、用户主档，和——

**客户托管数据。**

雪山银行的金融记录。还有两家医疗客户的健康档案。

**以明文的形态，导出到了异地容灾的存储桶里。**

沈见微坐在战情室的角落，周围是回升曲线带来的、渐渐松下来的空气——有人在低声欢呼，有人开始讨论今夜谁值守。没有人注意角落里那个一动不动的背影。

她盯着屏幕上那行"backup-export-daily：成功"，盯了很久。

然后她抬起头，目光离开屏幕，落在了虚空里的某个点上，愣了三秒。

三秒钟里，一个问题在她脑子里成形。这个问题从周一凌晨两点就等着了，等了三十九个小时，终于等到了唯一一个会问它的人：

**密钥失效的那四十六个小时里，跑过什么任务？**

她低头，查了第二件事：那个异地容灾存储桶的**访问策略**——明文数据躺在桶里，桶的门，开着几扇？

查询需要权限。她的权限不够——存储桶的权限管理在平台侧。她抬头找老涂："老涂，帮我查一个桶的访问策略，异地容灾的主桶，周一凌晨之后的访问日志和策略变更记录。现在。"

老涂查了。

两分钟后，他把结果调出来，投到她旁边的副屏上。

沈见微看了一眼，站了起来。

她站起来的动作太急，椅子在地上刮出很响的一声。周围几个人回头。她顾不上了——她穿过整个战情室，径直走向主桌，走向程亦朗。

"程总。"她的声音不大，但那个音量是她只用过两次的音量——一次是雪山，一次是现在。"用户打不开的问题在好转，两个小时后基本恢复。**但我们需要立刻谈另一件事。不是技术问题。**"

"什么？"

她看了一眼四周。战情室里还有三十多个人，其中有一些面孔，她此刻已经无法判断立场。

"单独谈。"她说，"您，我，江总——**还有法务。**"

程亦朗看着她的眼睛。看了两秒钟，他看见了那双眼睛里的东西——那不是疲惫，不是愤怒，是一种他只在最坏的电影里见过的、知道自己手里拿着什么的那种冷静。

他转身对全场说："今晚大家辛苦。曲线稳住后按值守表轮休。"然后他对沈见微说了两个字：

"楼上。"

---

上楼之前，她给江叙白发了一条消息。董事会散了吗，他今晚始终没有出现在战情室——后来才知道，散会后他被几个股东代表缠住了，此刻刚脱身，正在往回赶。

她的消息只有一行：

"回来直接上顶楼。**别去战情室。**我们可能闯了大祸——不是故障的那种大祸。"

发出去，送达。

三秒后，"已读"。

然后，几乎立刻，电话打了进来。她接起来，还没开口，那边的声音先到了——一天里被静音了两小时的那个人，此刻的声音是绷着的：

"说。"

"备份。"她说，"周一凌晨的例行备份，明文，三家客户，导出到了容灾桶。**桶的访问策略，在周一白天的一次连锁故障处理里，被临时改过——改成了'公开可读'。**"

电话那头，安静了整整五秒钟。

五秒钟之后，她听见了这个她认识了四年的人，第一次失声：

"**……多少数据。**"
