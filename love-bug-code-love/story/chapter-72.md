# 第七十二章 配置瘦身

三月底，乔曼做了一件让整个技术治理小组都没料到的事。

她在小组例会上主动请缨，接了一个没人要的活。

"加固方案通过了，接下来是落地。"她把一页纸推到桌子中央，"落地里最大的一块是'配置中心统一收口'——统一之前，得先做存量清理。我们平台侧积压了四年的孤儿配置，没人认领，没人敢删。我提个专项：**配置瘦身**。降本增效，清理僵尸配置，为统一收口扫清障碍。"

她说完，会议室里安静了几秒。

所有人都以为她要体面退场了。

方案之争输给江叙白之后，她本可以坐在双牵头的位置上安静地熬——熬到上市结束，熬一个"虽然方案没被采纳但全程配合"的评价。这是大多数人会选的路。主动去接一个清理僵尸配置的脏活，等于把自己从"架构之争的落败方"降格成"收口工程的清道夫"。

"降本增效"这四个字在筹备组是敏感词——好的那种敏感。上市材料里，成本结构是投资人最看的章节之一，任何能写进招股书的降本数字，都是真金白银的估值加分。

秦立群先表态："可以。降本的数字，披露口径里用得上。"

陈临翻着那页纸："预算呢？"

"三个人月，零新增资源，全部用平台侧现有人力。"乔曼答，"我自己的团队消化。"

"周期？"

"八周清理，四周验证。上市窗口之前收尾。"

陈临点头，这事就这么定了。散会的时候，有两个委员在走廊里交换了一下眼神，那个眼神的意思翻译过来是：输了一场大的，赶紧找个体面的小事翻篇——也难得，没闹情绪，肯干实事。

这两个人一路走出会议室，谁也没多看一眼那页纸的背面。

---

立项书是乔曼自己写的。

不是让下属起草再改——是逐字自己写的。写这份立项书她花了六个晚上，每一晚都在做同一件事：**删**。

删掉所有形容词。删掉所有可以有多种解释的词。删掉所有"建议""酌情""视情况"。

她比公司里任何人都清楚，一份经得起推敲的文件是怎么长出来的——因为她是被推敲了三年的人。雪崩案的复盘报告怎么被磨损的，她全程在场；她自己的材料怎么被沈见微的注释钉死的，她逐字读过。磨损一份文件和做实一份文件，用的是同一门手艺，方向相反。

立项书定稿三页半。摘要一百二十字。目标：**"清理平台侧存量无效配置，释放配置中心容量与维护成本，为统一收口建立基线。"** 范围：列了十一条配置域，每一条都标了"经平台侧 2023-2026 变更记录比对确认，三十天内无引用"。方法："三步走——扫描识别、灰度摘除、观察验证。"每一步的回滚方案单独成节，写了整整一页。

风险一节她写得最狠。别人写风险是凑数，她写风险是堵嘴——她把评审会上所有可能被问的问题全部预先列出来，逐条给出控制措施。共九条。第九条是："本专项不涉及任何在用配置的删除；所有删除动作须经双人复核并在变更窗口执行。"

这一条后来救了她。因为它是真的——至少，字面上是。

---

立项评审会，江叙白主持。

他看文件有一个习惯，是从老严那里传下来的：先看风险一节。他说过，一份方案的目标可以吹，预算可以砍，只有风险一节藏不住人——写风险的手松手紧，就是做事的人胆大胆小。

乔曼的风险九条，他逐条看了。看完，往回翻，看范围十一条，再往回，看摘要。

会议室里很安静。所有人都在等主席的评审意见——技术治理小组的项目，江叙白的意见基本就是结论。

他看了很久。久到乔曼都开始在心里预演他可能问的问题——她准备了他可能问的每一个问题的答案，其中三个问题的答案她设计了三层防线。

他一个都没问。

他合上立项书，只说了一句："第九条，'双人复核'的复核人，指定名单报我一份。"

"当然。"乔曼说。

"通过。"

两个字。评审结束。

散会后，方姐在电梯里跟江叙白同乘。方姐说了句公道话："这份立项书写得干净。挑不出错。"

江叙白"嗯"了一声。

电梯到了一楼。门开了，他先出去，走出去两步，又停了一下。方姐跟在后面，听见他自言自语似的说了一句：

"太干净了。"

方姐没听懂："什么？"

"没什么。"江叙白说。他站了半秒，像是要把某个念头抓回来，但那个念头没有形状，只有一点重量，一闪就沉下去了。"走吧。"

他没有再想下去。后来很长一段时间，他都没有再想下去。一个挑不出错的文件，你能拿它怎么办呢？技术世界里的规则很诚实：干净就是干净，无懈可击就是无懈可击。他放行了。放行单上签了他的名字，钢笔字，三个字，落在他此生签过的最贵的一张通行证上。

而他不知道的是——那份立项书，乔曼写完之后在自己家里读了七遍。每一遍只读一个地方。

---

立项书一共三个附件。

附件 A：十一条配置域的清单，带变更记录比对。附件 B：回滚预案。附件 C：**清理脚本的技术说明**。

附件 C 是立项书正文之外的技术细节，按流程属于"随立项材料归档、不进评审正文"的部分——因为脚本本身还没写，附件 C 只是设计说明：脚本的目标、接口、以及一段参数说明。

参数说明的第三行，混在十几行正常的脚本参数中间，有一行小字：

**"清理脚本边界值：默认 86400，详见脚本实现。"**

86400。二十四小时的秒数。在脚本参数的语境里，这是一个"清理操作的观察窗口时长"——清理一个配置后观察二十四小时无异常，才物理删除。完全正常的参数。任何人看到它，最多觉得"挺规范，还带观察窗口"。

评审那天，这行字随着附件 C 一起，进了归档系统。审批链上一共七个签名。没有人多看它一眼。

一个参数的定义，静静躺在档案柜里，等它的脚本。

---

四月初，专项启动。

乔曼的团队进了三个人：老涂，她条线里最老实的老工程师，干活不看方向；一个外包；一个刚转正的应届生。她自己挂帅，但日常只出现半点钟——她还在技术秘书和双牵头的位置上，忙，这是所有人眼里的正常状态。

清配置的活在别人看来枯燥得冒烟：跑扫描、看引用、摘配置、盯观察窗口、记录、归档。八周清理期，第一周就清出了两千多条孤儿配置，降本数字很好看，秦立群在筹备组会上还引用了这个数。

没有人注意到，乔曼每天出现的那半小时，看的从来不是清理进度。

她看的是**变更通道**。

统一收口之后，平台侧所有的配置变更都要走新的通道：双签、留痕、窗口期。而"清理专项"的脚本，因为立项书里白纸黑字写着"在变更窗口执行批量摘除"，拥有一个别的变更没有的东西——**批量的、脚本化的、一次成百上千条的处理能力**。

脚本每处理一条配置，都要读取它的邻居——同一个配置块里的相邻参数段。这是清理脚本的技术必然：你要确认一个配置没被引用，就得把它周围的引用关系全部遍历一遍。

遍历。这个词在清理的语境里无辜至极。

乔曼要的从来就不是那份立项书批准的清理范围。她要的是这个脚本的**存在本身**——一个合法的、经过七级审批的、每天在配置中心里跑来跑去读遍所有配置块的工具。一个被审计过、被双签过、被写进了回滚预案的完美通道。

至于脚本读到了什么、没读到什么、读到的部分将来会被怎样使用——那是脚本实现层面的事。脚本实现，不需要过评审会。

需要过评审会的，只有一个边界值。

86400。

---

四月中的一个晚上，办公室走了空。

乔曼留在最后。她打开配置中心的管理界面，调出清理专项的脚本设计稿——附件 C 对应的实现版本，还在开发中，老涂按部就班地写着主体逻辑。

她把光标移到参数区，那一行小字所在的位置。

**清理脚本边界值：默认 86400。**

她看着这行数字，看了很久。

窗外是四月夜晚的城市，写字楼的灯一格一格地亮着，每一格里都有人在为上市加班。她自己也是其中一格。这栋楼里的所有人都以为接下来的一年是一场冲刺——把数据做实，把口径谈拢，把钟敲响。

只有她知道，冲刺的跑道上，还有另一个倒计时。它不出现在任何人的甘特图上，不进任何一份周报，它只在一个脚本的参数区里，以一行小字的形态，安静地呼吸。

86400 秒。二十四小时。

这个数字以后会变成什么，此刻只有她一个人知道。而她的立项书写得那么干净，干净到连江叙白——那个看文件先看风险、能从一份方案里读出九年记忆的人——都只说了一句"太干净了"，然后放行。

太干净了。

他在电梯口说的那四个字，这几天在乔曼心里回放过两次。每一次回放，她得出的结论都一样：他闻到了味道，但味道不是证据。一份挑不出错的文件，是这个世界能给她的最好的盾牌——因为规则站在文件这边。

她想起老严——没见过面，只在传闻里存在的那个人——传闻里说，江叙白从他那里学到的最重要的东西是"技术问题技术解决"。

好。她想。那就技术解决。

她按下保存，关掉界面，收拾东西离开。走廊的声控灯一段一段地亮起来，又在她身后一段一段地灭下去，像一条只活几秒钟的路，刚好够一个人走过去。

大楼外面，春天夜里的风是暖的。

配置中心里，八万六千四百这个数字睡着。

在它醒来之前，还有很长的路要走：脚本要写完，边界要"调整"，时机要等——等一个所有人都在看别处的时候。

不急。

立项书已经批了。跑道已经扫干净了。附件 C 在档案柜里，安安静静地，朝着灾难的方向，翻开了第一页。
