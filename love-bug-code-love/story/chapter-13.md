# 第十三章 缓存之夜

大促前最后一个平静的下午，是被奶茶打破的。

"周年庆保障指挥部的第一波物资到了！"行政姑娘推着小车挨层派发，"红牛、咖啡、士力架、眼药水——最后这个是程总特意让加的，说技术线的朋友们这个礼拜都用得上。"

沈见微领了两罐红牛和一瓶眼药水。研发区的气氛从下午三点就开始变了：平日五点半就走一半人的开放区，今天没有一个人动；走廊里的人走路都比平时快半拍；电梯间的白板上贴着一张手绘的倒计时——**距周年庆开抢：27 小时**。

灵犀的周年庆大促，是全年最大的一次流量洪峰。平台上的商家提前半个月就开始铺预热页，开抢那一小时，流量会是平日的十倍。对技术条线来说，这等于一场提前通知的战役——弹药的筹备从上个月就开始了：扩容演练压了三轮，预案手册写了四十页，值班表排到了小时。

值班表上，沈见微的名字在"攻坚组支援"一栏。流量染色课题上周刚完成全量放量，正好赶上这场大促当第一次实弹检验——她的影子验证链路会在洪峰里跑全程，真实流量、真实峰值、真实的一切。课题的最终验收，就看这一夜。

"紧张吗？"傍晚在食堂，温遥问她。

"不紧张。"她扒着饭，想了想，补了一句实话，"怕丢人。课题跑了三个月，要是明天峰值一来指纹全乱，我下周一就得在复盘会上表演什么叫'理想很丰满'。"

"你就是嘴硬。"温遥笑着摇头，把一筷子青菜夹到她碗里，"多吃点，听说你们今晚全员守到十二点。"

---

晚上七点半，研发区灯火通明。

大促开抢是明晚八点，今晚是预热夜——预热页的秒杀预约通道八点放量，流量大约是明日洪峰的三分之一，属于战役的"前哨战"。各岗位提前就位：网关组盯着限流阈值，数据库组守着连接水位，应用各组在自己的值班群里报数。

攻坚组这边，老康把大屏调成了三块监控：流量染色链路的补标精度曲线、全站缓存命中率、和一张整体大盘。曲线们安安静静地趴在各自的基线上，像手术前的心电监护。

"都正常。"老康伸了个懒腰，"我看今晚可以躺到十二点。"

七点五十八分，沈见微看见自己那条补标精度曲线轻轻跳了一下——99.7 跌到 99.2，又爬回来。

预热流量进来了。链路咬住了。她在值班群里报：**"攻坚组：影子链路正常，补标精度 99.2，波动在预期内。"**

群里一片绿色。八点、八点半、九点，预约量一路爬，爬到平日的四倍，各系统稳稳接住。值班群里开始有人发轻松的段子，有人开始讨论宵夜订什么。

九点四十，周昊抱着笔记本电脑串门来了。他今晚守平台组的缓存条线，脸色红润，精神抖擞，一坐下就开始吹：

"跟你说，今晚缓存这块稳得像 welded 的一样。命中率 98.6%，一点不带抖的。"他凑近压低声音，得意得眉毛都在飞，"知道为什么吗？我上礼拜合了个优化——缓存 SDK 的初始化参数，以前那套配置写得跟随机漫步似的，我给规整了。组长 review 的时候还夸了，说'终于有人管这摊了'。"

"规整了什么？"

"TTL 呗。"周昊说得云淡风轻，"以前那代码里，缓存的过期时间东一个随机值西一个随机值，乱七八糟。我给统一了——热点 key 统一一个过期档位，管理起来清爽多了。大促前正好赶上，等于是给缓存做了一次大扫除。"

沈见微"嗯"了一声，没太往心里去。她当时的全部注意力都在自己的补标精度曲线上——十点零五分，预约流量冲到第二个小高峰，精度抖到 98.9，又稳住。

她后来无数次想起这个晚上。想起周昊坐在她旁边，得意洋洋地说"统一了""清爽多了"，而她"嗯"了一声，继续看自己的曲线。

那七秒钟的对话里躺着一场灾难的全部种子，而她当时什么都没听出来。

---

明晚八点整，开抢。

七点五十九分，全体值班群里安静得像战壕。八点整，洪峰如期而至——流量曲线像一堵墙一样立起来，直冲十倍基线。

八点零二分，一切正常。

八点零四分，一切正常。

八点零六分，全站缓存命中率开始跳水。

98.6——95——88——79。曲线不是下滑，是塌方。四秒钟，跌破 50%。

"命中率怎么了？！"值班群里炸了第一声。

命中率塌方的下一秒，回源流量曲线开始垂直爬升——缓存里没有的数据，全部砸向数据库。数据库连接数冲破警戒线，CPU 一分钟内干到 100%。应用的接口超时告警开始连环弹：

**【P0】商品详情接口超时率 47%↑**
**【P0】库存查询服务不可用**
**【P1】营销价格服务响应超时**
**【P0】交易下单链路熔断**

告警像雪崩一样，一条压着一条，红色的海洋把所有值班群同时淹没。

战情室的方向传来脚步奔跑声。有人开始喊"降级！降级！""限流放多少！""数据库先扩只读！"

沈见微坐在原地没动。

她面前的三块监控里，左边那块是她自己的链路——补标精度在大盘雪崩中抖得像筛糠，但那是结果不是原因。右边那块是全站大盘，红色一片。而中间那块，缓存监控，她的目光钉在其中一个不起眼的小图上——

**key 过期速率（expired keys/sec）。**

那张图的形状不对。

正常的业务缓存，key 的过期应该是"下雨"——每一秒都有一些 key 到期，速率曲线是一条贴着地面的、微微起伏的毛边线。哪怕大促期间写入量十倍，过期速率也只是相应抬高，仍然是毛边的、下雨一样的。

而现在这张图上，在 20:06:31 那一秒，立着一根针。

一根又高又窄、几乎是几何学的针尖——单秒过期量两百三十万。她把视图拉近，近到秒级：那一秒之前，正常；那一秒之后，骤然回落；紧接着 20:06:47，第二根针；20:07:02，第三根——间隔精确得像节拍器，十六秒，十五秒，十六秒。

每一根针落下，命中率就塌一截，回源流量就垂直爬一截。

她在一片红光和喊声里，把值班群往上翻，找到缓存组的人："过期速率的监控，有人看过吗？为什么是尖峰？"

没人来得及回她。所有人都在救火，救火的人不看下雨的形状，只看火。

她不怪他们。她自己也说不清为什么，在满屏的红色里，只有那张小图让她后颈发凉——大概是三个月前那四十一个超时点教她的：真正的线索，往往长得毫不起眼，趴在一个所有人都路过的地方。

她开始自己查。调出缓存集群的采样分析，抓那一秒过期的 key 样本，看它们的 TTL 设置——

样本里的 key，商品详情缓存，TTL 全部是**同一个值**：600 秒。库存缓存，TTL 全部是 1800 秒。营销价缓存，TTL 全部是 900 秒。

整整齐齐。

没有随机抖动。

好的缓存实践她太熟悉了——她自己的影子链路里就写着：任何批量写入的缓存，TTL 必须加随机偏移，偏移量取 TTL 的正负百分之十到三十，让到期时间散布开来，像把一整杯水泼出去，而不是把一整块冰在同一个瞬间砸下来。

而现在这些 key——几百万个 key——是那块冰。

600 秒 TTL 的商品缓存，是在同一个时间片里被批量写入的（大促预热页，批量预热脚本干的），写入时间相同，TTL 相同，于是到期时间相同——两百万块一模一样的冰，在同一秒砸向数据库。第一批砸完，回建缓存的预热脚本又开始批量写入同样的 TTL，于是十六秒后，第二批冰准时落下。十五秒后，第三批。

节拍器。精确、整齐、致命的节拍器。

沈见微盯着那个 600 秒，指尖忽然有点凉。

统一档位。规整。清爽。大扫除。

昨晚周昊坐在这里，云淡风轻地说的每一个词，此刻在她的记忆里逐字亮起，像灾后废墟上一个个还连着电的指示灯。

她深吸一口气，点开缓存 SDK 的参数配置的版本历史——改动记录的头部一行字，就是她怕看见又必须看见的：

**最近一次配置变更：两周前，"缓存 TTL 策略统一化优化"**

她没再往下看点开提交人。不是不敢，是此刻不该——大厅里的告警还在炸，交易链路还在熔断，每过一分钟都是真金白银的 GMV 在流走。排查归属是复盘会的事，现在第一件事只有一个：

把节拍器停掉。

她抓起内线电话，拨了缓存条线的值班位。占线。再拨，还是占线。她站起来，逆着奔跑的人流，朝战情室方向喊出了今晚属于她的第一句话：

"缓存雪崩不是容量问题！是 TTL！统一的 TTL 没有随机抖动，批量预热的 key 在同一秒集中过期——先改预热脚本，TTL 加随机偏移再写入！改完一批，命中率回来一批！"

嘈杂的战情室门口，这声音不大，但它长得太不像慌乱里该有的声音了——它有因果，有节奏，有下一步。

好几颗头同时转过来。

江叙白站在战情室的白板前——大促技术保障的总指挥位。他看她的方向，隔着十几米的人声与红光，只说了两个字：

"进去说。"

---

后来的战报会这么写：20:06 雪崩爆发，20:19 应急方案上线（预热脚本停写+存量 key 用批量异步刷新续命+数据库限流保交易），20:41 缓存命中率回升至 92%，21:15 全链路恢复，P0 持续六十九分钟。

战报不会写的是：那根两百三十万的针尖图，是被一个入职三个半月的初级工程师在第一时间盯住的；也不会写，当晚十点四十分，救火收尾的间隙，她坐在战情室角落的电脑前，把 TTL 采样、过期速率尖峰、配置变更时间线整理成了一份东西——存档名她想了想，敲下去四个字：

**不像巧合。**

自然的过期是下雨，人为的过期是钟摆。

雨不会砸垮房子。

钟摆会。
